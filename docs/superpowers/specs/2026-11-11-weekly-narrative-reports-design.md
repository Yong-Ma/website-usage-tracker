# 叙事周报与本地提醒设计

## 目标

在不上传任何数据、不过度打扰用户的前提下，将现有的日级网站使用记录整理为可重复查看的叙事周报。用户可以选择每周提醒的星期和时间；提醒到达时，扩展生成一份不可变的本地报告快照，发送浏览器通知，并提供独立页面回看所有历史周报。

## 范围

本期包含：

- 每周提醒的开关、星期和时间设置；建议默认值为周日 21:00，开关默认关闭。
- 到点生成一份涵盖提醒前 7 个完整本地日的报告，并发送浏览器通知。
- 独立的扩展内「周报」页面，用时间线倒序展示报告摘要并查看完整报告。
- 弹窗内的「查看周报」入口。
- 报告、设置的中英文文案，以及导入导出兼容。

本期不包含图表、账户或跨设备同步、邮件推送、站点限制/拦截、手动补发周报，或将旧使用数据按小时重建。

## 用户体验

### 设置与提醒

「周报」页面顶部放置提醒设置卡片，提供：

- 启用/停用周报提醒的开关。
- 每周提醒日（周一至周日）和本地时间输入。
- 下一次计划生成时间。

首次启用时使用周日 21:00 作为预填建议，用户可保存后立即看到下一次提醒。弹窗不复制这些控件，只提供“查看周报”入口，避免设置在两个界面分叉。

提醒到达后，通知包含本周结论和一行摘要；点击通知会在新标签页打开对应周报。若操作系统已关闭此扩展的通知，报告仍然生成并可从周报页面查看；设置卡片显示提醒可能未展示的提示。

### 周报与历史

周报页面按生成时间倒序显示时间线。每张卡片展示：

- 报告日期区间与周序号。
- 一句叙事结论，例如“这周，你少花了 3 小时 2 分钟”。
- 总使用时长、变化最大的站点、使用最少的一天三个指标。
- “查看完整报告”操作。

完整报告显示前三网站、与上一周期的总时长变化、变化最大的站点以及最少使用日的解释。没有可比较的上一周期时，报告明确标为首份报告，不产生虚假的增减结论。没有任何使用记录时，不生成报告也不发送通知。

每份报告都是生成时的快照。后来清空使用记录、删除单站记录、调整排除网站或切换语言，都不改变历史报告中的统计结果；切换语言只改变同一快照的展示文案。

## 报告口径与数据模型

报告在本地时区按完整日统计。它的区间是计划提醒日之前的连续 7 个本地日；默认周日 21:00 提醒对应刚结束的上一个周日至周六。闹钟因休眠而延迟执行时，仍以其计划触发时间确定统计区间，避免把未结束日期混入报告。

新增两个 `chrome.storage.local` 字段：

```js
weeklyReportSettings: {
  enabled: false,
  weekday: 7, // 周日，1–7
  time: '21:00', // 24 小时制本地时间
}

weeklyReports: [{
  id: '2026-11-03_2026-11-09',
  rangeStart: '2026-11-03',
  rangeEnd: '2026-11-09',
  createdAt: 1794214800000,
  totalSeconds: 49200,
  previousTotalSeconds: 60120, // 无可比周期时为 null
  topSites: [{ origin: 'https://github.com', seconds: 15360, faviconUrl: '...' }],
  largestChange: { origin: 'https://bilibili.com', secondsDelta: -4860 },
  leastUsedDay: { dateKey: '2026-11-09', seconds: 2760 },
}]
```

`id` 由日期区间唯一确定，是报告去重键和通知跳转参数。报告存储归一化后的数值与站点信息；叙事标题和说明由纯函数在渲染时按当前语言生成。这样历史数据固定，同时保留中英文切换能力。

“变化最大的站点”按当期与上一期时长差的绝对值选取；并列时依次按当期时长从高到低、`origin` 字典序决定。前三网站按时长从高到低排序，时长相同也按 `origin` 字典序稳定排序。最少使用日覆盖区间内所有 7 天（允许为 0 秒），并列时选择更早日期。周报不自动清理历史快照。

旧安装没有这两个字段时，读取层提供上述默认值，不需要迁移步骤。备份格式升级为版本 2，包含两字段；导入版本 1 时补入默认设置和空报告列表，导入版本 2 时严格校验报告与设置结构。

## 调度、通知与后台流程

清单新增 `notifications` 权限，继续使用已有的 `alarms` 权限。后台维护一个命名为 `weekly-report` 的单次闹钟：

1. 扩展安装、浏览器启动、Service Worker 启动或用户保存提醒设置时，计算下一次符合星期与时间的本地时间，并创建或替换该闹钟。
2. 闹钟触发时，先结算当前活跃网站会话，再根据闹钟的计划时间计算报告区间。
3. 后台从当期和上一期的日记录聚合出报告；若当期有记录且该 `id` 尚不存在，则原子写入报告并创建通知。
4. 无论报告是否生成，后台都排定下一次未来闹钟。报告生成和闹钟重排纳入现有后台串行队列，避免与统计写入、清空或导入相互竞争。
5. 点击 `weekly-report:<id>` 通知时，后台打开 `src/reports/reports.html?report=<id>`。页面读取该 id 并将对应完整报告置于视野中。

闹钟可能延迟触发或在浏览器重启后丢失，因此不把“闹钟存在”当作数据真相：每次后台启动都检查并按已保存设置重新创建；报告 id 去重确保延迟触发、重试或重复事件不会产生多份同一周期的报告。

## 模块边界

- `src/shared/weekly-report-schedule.js`：纯函数，解析设置、校验星期/时间、计算下一次计划时间和报告日期区间。
- `src/shared/weekly-report-aggregation.js`：纯函数，按日期聚合当期/上一期使用数据，生成可存储的报告快照和叙事所需事实。
- `src/background/storage.js`：读取、校验并写入周报设置与快照；扩展 `readAllData`、`writeAllData` 和备份数据。
- `src/background/service-worker.js`：调度、报告生成、通知创建/点击，以及新增消息的串行处理。
- `src/reports/reports.html`、`reports.js`、`reports.css`：周报历史与提醒设置页面。
- `src/popup/`：增加打开周报页的本地化入口，不承担周报设置或报告渲染。

页面通过明确的后台消息读取/更新提醒设置；报告列表可经存储读取，或者由同一受控消息返回。页面不直接操作闹钟或通知，确保调度只由后台拥有。

## 错误处理与无障碍

- 保存前校验星期范围与 `HH:mm` 时间格式；无效设置保留旧设置并显示本地化错误。
- 创建闹钟或通知失败时，保留已生成报告，显示下次打开页面可见的状态提示，并在下次后台启动时重试创建闹钟。
- 不能找到通知对应报告时，通知点击打开周报历史页而非报错。
- 周报历史为空时显示解释性空状态和开启提醒操作。
- 开关、星期选择、时间输入和“查看完整报告”都有可见标签、键盘可达性和本地化文案；状态变化使用适当的 `aria-live` 提示。

## 验证

- 调度纯函数：默认值、所有星期、跨月/跨年区间、过去/当前时间、延迟触发时按计划时间取区间。
- 报告聚合：总时长、上一期比较、前三站点、最大正负变化、无前期数据、无当期数据及平局规则。
- 存储与备份：旧安装默认值、报告写入去重、版本 1 备份兼容、版本 2 往返与非法字段拒绝。
- 后台：重启后重建闹钟、保存设置替换闹钟、报告生成先结算会话、重复闹钟不重复报告、通知点击打开正确 URL。
- 周报页与弹窗：设置交互、空状态、历史排序、查询参数定位、通知禁用提示、中文和英文文案。
- 运行 `npm test`，并在 Chrome 开发者模式下手动验证一次即时调度、通知点击和导入旧备份。
