# 排除网站界面设计

## 目标

让用户能够在弹窗榜单中排除某个已记录的网站，并在设置面板中查看和恢复已排除的网站。

## 范围

- 在每条网站榜单记录上提供“排除”按钮。
- 在设置面板中显示“排除网站”区块和已排除域名列表。
- 通过既有 `setOriginExcluded` 运行时消息更新排除状态。
- 中英文界面均使用现有翻译键。

不新增权限、数据结构、批量管理功能，且不删除任何历史统计记录。

## 交互

### 排除网站

1. 用户在榜单某行点击“排除”。
2. 弹窗以该域名显示确认提示。
3. 用户确认后，Popup 发送 `{ type: 'setOriginExcluded', origin, isExcluded: true }`。
4. 成功时重新读取使用数据与排除列表，重绘榜单和设置面板，并显示成功状态。
5. 失败时保持原状并显示失败状态。

后台现有逻辑会结束该网站当前会话，阻止后续时间记录。排除后，聚合榜单不显示该域名，历史使用数据仍保留在本地存储中。

### 取消排除

1. 用户在设置面板的已排除列表点击“取消排除”。
2. 弹窗显示恢复统计确认提示。
3. 用户确认后，Popup 发送 `{ type: 'setOriginExcluded', origin, isExcluded: false }`。
4. 成功时重新读取排除列表、刷新设置面板并显示成功状态。
5. 后续访问将从恢复时刻开始继续统计；历史记录不会被删除或自动重新显示为新增记录。

## 界面结构

设置面板在“暂停统计”之后插入一个“排除网站”区块，包含说明文本和列表。空列表显示“暂无排除网站”；非空列表逐项显示规范化域名和取消排除按钮。列表不支持新增：新增入口只在榜单行内。

榜单一行的操作区包含原有删除按钮和新增排除按钮。按钮具有可访问名称、`title` 和提交期间的禁用状态。

## 状态与错误处理

Popup 状态新增 `excludedOrigins`。初始化和导入成功后从 `chrome.storage.local` 读取该值。排除状态改变成功后再次读取该值，而不是在 UI 中猜测更新结果。

确认被取消时不发消息。请求在进行时只禁用被点击的操作按钮；失败时重新启用该按钮，并在既有状态区域显示本地化错误信息。

## 测试

- 扩展现有国际化测试，确保排除相关的全部中英文文案可解析。
- 新增 Popup DOM 交互测试，验证排除请求的消息内容、成功后的重新渲染和失败恢复。
- 新增 Popup DOM 交互测试，验证设置面板的空态、已排除列表和取消排除请求。
- 运行 `npm test`，确保既有后台排除逻辑与新增界面测试全部通过。

## 验收标准

- 用户可从任意可见榜单行排除网站。
- 被排除网站不会出现在使用统计中，且不再累积新时长。
- 设置中能够查看每个被排除网站并恢复统计。
- 操作确认、按钮描述、成功和失败反馈均正确本地化。
- 历史数据不会因排除或恢复被删除。
