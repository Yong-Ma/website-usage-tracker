# JSON 备份与恢复设计

## 目标

让用户在卸载扩展前导出全部本地数据为 JSON 文件，并在重新安装后导入该文件，恢复网站时长统计和全部用户设置。

## 范围

备份包含当前由扩展维护的持久化本地数据：

- `usageByDate`：按日期保存的网站使用时长。
- `trackingPaused`：暂停统计状态。
- `excludedOrigins`：排除统计的网站列表。
- `popupLanguage`：弹窗界面语言。

不包含 `chrome.storage.session` 中的临时活跃会话。导入完成后由后台服务重新建立当前会话，避免把已过期的会话带回。

## 方案

在弹窗的设置面板加入两个操作：

- **导出数据**：读取上述全部本地存储字段，生成一个用户下载的 JSON 文件。
- **导入数据**：用户选择此前导出的 JSON 文件；弹窗读取、校验并发送给后台服务。后台服务串行执行导入，避免与正在写入的使用时长产生竞争。

文件使用一个明确的备份包结构：

```json
{
  "format": "website-usage-tracker-backup",
  "version": 1,
  "exportedAt": "2026-08-30T00:00:00.000Z",
  "data": {
    "usageByDate": {},
    "trackingPaused": false,
    "excludedOrigins": [],
    "popupLanguage": "zh"
  }
}
```

`format` 和 `version` 用于识别本扩展生成的文件及以后兼容格式演进。`exportedAt` 仅供用户查看，不参与恢复逻辑。

## 导入流程

1. 弹窗检查文件可读取且为 JSON，随后校验备份包结构与字段类型。
2. 用户确认后，弹窗向后台发送经过校验的备份数据。
3. 后台排队等待已有统计操作完成，结算并清除当前活跃会话。
4. 后台以备份中的完整数据覆盖四个持久化字段。
5. 后台根据恢复后的暂停状态重新刷新当前会话。
6. 弹窗重新读取数据和设置，刷新榜单及界面语言，并显示成功状态。

导入操作是“完整恢复”而非合并：备份中存在的字段将替代当前数据。这样恢复的结果可预测，也不会把重装后产生的少量新记录与旧记录重复叠加。

## 错误处理

- 文件不是 JSON、格式标识不匹配、版本不支持或字段不合法：拒绝导入，不改动当前数据。
- 文件读取、下载或后台写入失败：显示本地化错误提示；仅在后台开始写入前可保证原数据完全不变。
- 选择文件后取消确认：不执行任何写入。

导出时即使数据为空，也生成可重新导入的有效备份文件。

## UI 与可访问性

导入和导出按钮位于现有设置面板，沿用现有按钮样式。导入使用隐藏的文件选择控件，仅接受 `.json` 与 `application/json`。执行期间按钮禁用并以状态文本反馈结果；所有新增文字提供中文与英文翻译。

## 测试

- 存储层：导出包包含所有字段；有效包完整恢复；无效包不写入。
- 后台层：导入消息按现有队列处理，活跃会话被安全清除并重新建立。
- 弹窗层：备份文件的生成、解析与错误提示使用可测试的纯函数或最小 DOM 行为验证。

## 不做的事

- 不将持续增长的使用时长数据迁移到 `chrome.storage.sync`。
- 不引入账户、云端服务或自动远程备份。
- 不尝试读取已卸载或其他扩展 ID 的 Chrome 本地存储。
